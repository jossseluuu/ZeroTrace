# The certificates that protect your PC's startup expired this year: make sure it has the new ones

> What changed in Windows Secure Boot, why your computer still starts the same even if it isn't sorted yet, how to check in a minute, and what you don't need to touch.

## In a nutshell

When you turn on a Windows PC, before the logo appears, Secure Boot kicks in: the motherboard's firmware only lets software start if it's signed with certificates stored on the machine. That keeps malware from installing itself **underneath** Windows, where antivirus can't reach.

The certificates Microsoft put on nearly every computer built since 2012 had an expiration date, and **they've now expired**: on June 24, June 27, and October 19, 2026. Microsoft is replacing them with new 2023 certificates that arrive **through Windows Update**, with nothing for you to do on most machines.

The good news: a PC that doesn't have them yet **still starts and works normally**. What it loses is the ability to receive future fixes for the startup process itself. So it's worth a one-minute check, especially on a custom-built or older desktop.

**The essentials**

- The old Secure Boot certificates expired in June and October 2026; the replacements are from 2023.
- Your PC still starts without them, but it stops getting startup security fixes.
- Check **Windows Security > Device security > Secure Boot**: read the message, not just the icon.
- Don't turn off Secure Boot "to avoid problems": Microsoft explicitly advises against it.

**Real-world risk**

- **Likelihood: low.** Startup attacks against home users are rare: they need a specific flaw and usually an attacker who already has admin rights on the machine.
- **Impact: high.** Malware in the startup chain loads before Windows, can turn off protections like BitLocker, and survives many cleanups.

## How it works

### What exactly expired

Secure Boot relies on several lists stored in firmware: a database of allowed signatures, another of revoked ones (the DBX), and a key that authorizes changes to both. Microsoft had three 2011 certificates in those lists: the one that signs the Windows boot loader (**Microsoft Windows Production PCA 2011**, expired October 19, 2026), the one that signs third-party boot loaders and firmware (**Microsoft UEFI CA 2011**, June 27, 2026), and the one that allows updating the lists (**Microsoft Corporation KEK CA 2011**, June 24, 2026).

Their replacements are **Windows UEFI CA 2023**, **Microsoft UEFI CA 2023**, **Microsoft Option ROM UEFI CA 2023** (for firmware on expansion cards, such as many graphics cards), and **Microsoft Corporation KEK 2K CA 2023**. Microsoft says both the signature database and the key database need the new versions.

### What happens if your PC doesn't have them

According to Microsoft, the device **continues to start and operate normally**, and regular Windows updates still install. What it can no longer receive are updates to Windows Boot Manager, to the Secure Boot databases and revocation lists, and fixes for newly discovered vulnerabilities in the boot chain.

In other words, there's no blackout: there's a machine that slowly falls behind on patches in its most sensitive layer. Microsoft adds that some third-party components that rely on its signature may fail to update.

### Why desktops deserve a look

On most machines, Windows Update applies the certificates by itself. But Microsoft warns that some devices need **a firmware update from the manufacturer**, which may only be available for devices still within their support period. On a custom-built desktop, that manufacturer is your **motherboard** maker.

Devices with Secure Boot turned off won't get them either (common on older PCs or ones tweaked to install another OS), and neither will Windows 10 PCs outside the Extended Security Updates (ESU) program since October 14, 2025.

### The small risk of the switch

Microsoft acknowledges that when the new certificates arrive, some devices may ask for the **BitLocker recovery key** (48 digits) or, rarely, fail to start. That's no reason to avoid the update, but it is a reason to know where that key is first.

## What an attack looks like

1. **The starting point.** An attacker has already managed to run a program with admin rights on your PC, for example through a fake installer.
2. **Dropping into startup.** It plants an old boot loader, legitimately signed but with a known flaw, to bypass Secure Boot. That's what BlackLotus did, as analyzed by the NSA in 2023.
3. **Turning off defenses.** From there, BlackLotus disabled Memory Integrity and BitLocker and rebooted the device, loading ahead of Windows on every startup.
4. **The defense.** Microsoft's fix is to **revoke** the old boot loaders signed with the 2011 certificate (by adding it to the DBX). That's only possible on devices already booting with software signed by the 2023 certificate.
5. **Your part.** Having the new certificates and Secure Boot turned on is what lets those revocations and future fixes reach your PC.

## What an attacker can and can't do

**Can**

- Exploit a startup flaw that has already been fixed, if your device can't receive the new updates.
- Install itself underneath Windows if Secure Boot is turned off.
- Disable protections like BitLocker or Memory Integrity once inside the startup chain.
- Keep abusing old boot loaders until they're revoked on your device.

**Can't**

- Attack your PC's startup just because the certificates expired: expiration doesn't open a door by itself.
- Reach the startup chain without first running something with high privileges on the device or having physical access.
- Make your PC stop starting because of the expiration: Microsoft confirms it keeps working.
- Undo a revocation that's already applied by reinstalling Windows or reformatting the disk: per Microsoft, revocations persist.

## What to do

### Check the status in Windows Security

`Impact: high` `Effort: low` `⏱ 1 min` `For: everyone`

Microsoft shows certificate status in the app. Read the message: per Microsoft, a green check mark alone doesn't confirm the certificates are updated.

**Windows 11**

1. Open **Windows Security > Device security > Secure Boot**.
2. **Fully updated**: nothing to do. **Not yet updated**: install pending updates and restart. **Requires action**: follow the message (usually, contact the manufacturer).

### Don't pause Windows Update, and restart when asked

`Impact: high` `Effort: low` `⏱ 5 min` `For: everyone`

That's how the certificates arrive. Microsoft asks for a supported version of Windows, updates not paused, and Secure Boot turned on.

**Windows 11**

1. Go to **Settings > Windows Update** and select **Check for updates**.
2. If updates are paused, select **Resume updates** and restart when it finishes.

### Find your BitLocker recovery key first

`Impact: medium` `Effort: low` `⏱ 5 min` `For: everyone`

If the certificate change asks for it, you'll need to type all 48 digits. If your drive was encrypted with a Microsoft account, it's usually stored there.

**Windows 11**

1. From another device, go to **account.microsoft.com/devices/recoverykey** and sign in with your Microsoft account.
2. Make sure this PC's key is listed and save it in your password manager or on paper.

### If it says "Requires action," look for your motherboard's firmware

`Impact: high` `Effort: medium` `⏱ 20 min` `For: everyone`

Microsoft says some devices need a firmware update from the manufacturer. For a brand-name desktop, check its support site; for a custom build, check your motherboard maker's site for the exact model.

**Windows 11**

1. Press **Windows + R**, type `msinfo32`, and note **BaseBoard Manufacturer** and **BaseBoard Product**.
2. Look up that model on the manufacturer's official site and follow its instructions to update the firmware (BIOS/UEFI). If there's no new version, contact its support.

### Check the certificates with PowerShell

`Impact: low` `Effort: low` `⏱ 2 min` `For: advanced`

To confirm what's actually in the signature database without relying on the app's message.

**Windows 11**

1. Open **Terminal (Admin)** and run `Get-SecureBootUEFI -Name db -Decoded` (available since the April 14, 2026, cumulative updates).
2. You should see `CN=Windows UEFI CA 2023`. You can also check the `UEFICA2023Status` value under `HKLM:\SYSTEM\CurrentControlSet\Control\SecureBoot\Servicing`: it should read `Updated`.

### Refresh your recovery USB

`Impact: low` `Effort: medium` `⏱ 30 min` `For: paranoid`

Microsoft warns that once the old boot loaders are revoked, older recovery media may no longer start the device. One created after you have the new certificates saves you a scare.

**Windows 11**

1. Search Start for **Create a recovery drive**, plug in a USB drive, and follow the wizard.

## Check it yourself

- **Does the message say "Fully updated"?.** Under **Device security > Secure Boot**, the text should say Secure Boot is on and all required certificate updates have been applied.
- **Is Secure Boot on?.** In `msinfo32`, the **Secure Boot State** line should read **On**.
- **Do you have your BitLocker key handy?.** Check your Microsoft account today, not the day your computer asks for it.
- **Is Windows Update current?.** No paused updates and no restart pending for weeks.

## What you don't need to do

- **Turning off Secure Boot.** Microsoft is clear: it shouldn't be disabled to work around certificate expiration, because that significantly reduces protection against boot-level malware.
- **Updating the BIOS "just in case".** If the app says fully updated, you don't need to. Firmware updates carry their own risk and are only worth it if the status calls for one or the manufacturer recommends it.
- **Reinstalling Windows or replacing your PC.** The expiration doesn't break anything: the device keeps starting. It usually resolves itself through Windows Update.
- **Apps that promise to "fix" Secure Boot.** The certificates come through Windows Update or the manufacturer's official firmware. There's no other legitimate route.

## Myth and reality

- **What people think:** "Once the certificates expire, my PC won't start."
- **What actually happens:** Microsoft explains that a device that reaches the expiration date without the new certificates **will still start and operate normally**. What it loses are startup security updates, such as Boot Manager updates and revocation lists. ([Microsoft: When Secure Boot certificates expire on Windows devices](https://support.microsoft.com/en-us/servicing/os/secure-boot/2026/02/when-secure-boot-certificates-expire-on-windows-devices))

## For technical readers

### PK, KEK, DB, and DBX

UEFI firmware stores the manufacturer's Platform Key (PK), the KEK (keys authorized to modify the databases), the DB (allowed signatures and hashes), and the DBX (revoked ones). Windows updates the active variables; the manufacturer's firmware also updates the defaults. That's why Microsoft warns that if firmware is reset to factory defaults lacking Windows UEFI CA 2023 after revocations are applied, Secure Boot will block startup and you'll need recovery media.

### CVE-2023-24932 and revoking PCA 2011

BlackLotus exploited CVE-2022-21894 (*Baton Drop*) by loading an old, vulnerable boot manager. The underlying mitigation, documented for CVE-2023-24932, is to add Windows UEFI CA 2023 to the DB, boot with a manager signed by it, and then add **Windows Production PCA 2011** to the DBX, which untrusts every boot manager signed by that certificate. Microsoft warns this can't be reverted while Secure Boot is in use and that the mandatory enforcement phase will be announced with at least six months' notice.

### Useful checks

On systems without the `-Decoded` parameter, Microsoft suggests `[System.Text.Encoding]::ASCII.GetString((Get-SecureBootUEFI db).bytes) -match 'Windows UEFI CA 2023'`, which returns `True` if the certificate is in the DB. Before touching BitLocker-protected machines, back up the protectors with `manage-bde -protectors -get %systemdrive%`. If you build or ship UEFI loaders or drivers signed with Microsoft UEFI CA 2011, plan for signing under the new Microsoft UEFI CA 2023 or Option ROM UEFI CA 2023.

## Glossary

- **Secure Boot:** A UEFI firmware feature that only lets software start if it's signed with trusted certificates stored on the device.
- **UEFI firmware:** The motherboard software that runs when you turn on the computer, before Windows. It's the successor to the old BIOS.
- **DBX:** Secure Boot's list of revoked signatures: anything on it can't start, even if it's signed.
